# Echo Show 5 (2nd gen) changelog

All notable changes to the Echo Show 5 (2nd gen) (`cronos`) image are documented here. The [Echo Dot (2nd gen)](CHANGELOG-biscuit.md) and [Echo Show 8 (1st gen)](CHANGELOG-crown.md) have their own.

## 2026.10.5 - 2026-10-30

### Added
- **Double tap to wake** ([#25](https://github.com/jxlarrea/lineageos-echo-kiosk-satellite/issues/25)). Android offered a Double tap to wake setting, but it did nothing. The touch chip kept scanning while the screen was off, but the touch driver dropped the first touch and then stopped listening until the screen came back on. The driver now turns the screen on when two touches start within 400 ms of each other. No other touch reaches Android while the screen is off. Android's Double tap to wake setting turns it on and off. It is on by default.

### Fixed
- **GApps and Magisk survived an install of this image** ([#27](https://github.com/jxlarrea/lineageos-echo-kiosk-satellite/issues/27)). LineageOS runs its backup tool in every zip it builds for testing, which the Echo images are. It saves what `/system/addon.d` lists before the zip writes the system partition and puts it back after. Moving from another image with GApps or Magisk, such as R0rt1z2's, kept them, even with the data wiped. An account GApps added could then keep Kiosk Satellite from becoming the device owner. EchoService only takes an update from the device owner. The zip no longer runs the backup tool, so an install writes exactly this image. `make check` fails a zip that runs it. This fix applies to every Echo. The Echo Show 5 guide says what carries over from R0rt1z2's image and how to check that Kiosk Satellite is the device owner when an update does nothing.
- **Apps crashed when a filled-in text field became visible** ([#24](https://github.com/jxlarrea/lineageos-echo-kiosk-satellite/issues/24)). The image leaves out Android's autofill service to save memory, but Android's autofill code still called it when a text field that already had text and no focus came into view. The app crashed with a NullPointerException, for example YouTube Morphe on saving its settings to a file. Android now skips autofill when the service is not there. This fix applies to every Echo.
- **The device in a release zip's `release.prop`.** It read `ro.product.device=None` on every Echo Show release. Android 11 keeps `ro.product.device` out of the system `build.prop`, which the release step read it from. It now reads `ro.product.system.device`. Nothing used the line, since EchoService checks the device in the zip's metadata, so updates were never affected. `make check` now fails a release zip that names another device.

### Changed
- **One changelog for each device.** `CHANGELOG.md` is now `CHANGELOG-biscuit.md`, `CHANGELOG-cronos.md` and `CHANGELOG-crown.md`, with release headings such as `## 2026.10.15 - 2026-10-29`. A build takes its release from its own device's changelog, so an Unreleased section for one Echo never touches another's builds.
- **Setting the time server.** The Echo Show 5 guide has a new Time section. It covers using your own NTP server instead of `time.android.com` and changing the time zone later with `echo_service time zone`. Android 11 ignores an NTP server the router hands out over DHCP ([#25](https://github.com/jxlarrea/lineageos-echo-kiosk-satellite/issues/25)).
- **Builds leave the rest of the host usable.** A build used to take every CPU and stall the whole host until it finished. The build container now gets half the CPUs at the lowest priority and half the memory without swap, with one job for every 5 GB. `BUILD_CPUS`, `BUILD_MEMORY` and `BUILD_JOBS` change the limits. [Building](docs/building.md) covers them.

## 2026.10.4 - 2026-10-29

### Fixed
- **The camera HAL ran the Show 5 out of memory when the camera stayed open** ([kiosk-satellite#1209](https://github.com/jxlarrea/kiosk-satellite/issues/1209)). MediaTek's camera HAL was built for Android 9. For every frame it creates two objects that Android 11 no longer frees completely, so `camerahalserver` grew by about 35 bytes a frame and logged six lines a frame while the camera was open. With Kiosk Satellite's motion detection on, that came to up to 3 MB an hour. After about 10 days the swap filled and the low memory killer started closing apps, Kiosk Satellite included. The shim the camera HAL loads now frees those objects as Android 9 did, and its memory stays flat.
- **Music could sound tinny and warble while Kiosk Satellite listened** ([#20](https://github.com/jxlarrea/lineageos-echo-kiosk-satellite/issues/20)). Amazon's audio driver moves playback onto its call path whenever a microphone capture starts. That path is made for calls: it filters out the bass and turns playback down while it hears the microphones. The audio HAL only took playback back off it for the microphone captures it reroutes itself. With Capture mode set to Voice communication in Kiosk Satellite, or after Kiosk Satellite fell back to that source by itself, music stayed on the call path for as long as the microphones were open. Playback now leaves the call path at the start of every capture unless Android is in a call.

## 2026.10.3 - 2026-10-27

### Fixed
- **A system update from TWRP 3.2.3 could leave the Show in a boot loop** ([#13](https://github.com/jxlarrea/lineageos-echo-kiosk-satellite/issues/13)). The image needs amonet 2 and its TWRP 3.7.0_9-0, but an update runs in whatever TWRP the Show has. On a Show still on amonet 1 and its TWRP 3.2.3, the update left the system half written. The update step in TWRP now checks the TWRP version first. With anything other than 3.7.0_9-0 it writes nothing and starts Android again, and EchoService reports why in Home Assistant and Kiosk Satellite. This applies to updates from this release on.
- **Camera streams and videos in High profile H.264 fell back to software decoding** ([#15](https://github.com/jxlarrea/lineageos-echo-kiosk-satellite/issues/15)). MediaTek's hardware decoder told Android it handles High profile only at its lowest level, although it decodes High up to level 4.1 at 1080p at about 150 frames a second. Its size limit also read as at most 1088 pixels high, which ruled out portrait video. Kiosk Satellite's WebView and players such as ExoPlayer then used Android's software decoder, which is about four times slower on the Show and stalled camera streams. Android now lists High profile up to the same level as Main for this decoder and accepts portrait video up to 1080x1920, so these streams play on the hardware decoder.

## 2026.10.2 - 2026-10-27

### Fixed
- **Streaming stalled on Wi-Fi networks with several access points.** Android 11 looks for a better access point after every scan while a connection carries little traffic. The Echos' Wi-Fi drivers report no traffic at all. On a mesh network Android moved an Echo Show 8 between access points every 20 seconds, even in the middle of a voice conversation. Each move stalled audio and dropped Home Assistant. Android also ranked access points by a throughput estimate that these drivers get wrong, so it picked a weak mesh node over the router next to it. Android now keeps the access point it connected to and picks one by signal strength, preferring a 5 GHz network down to -50 dBm. This applies to every Echo. On the Echo Show 5, a scan while connected stalled the link in bursts of up to half a second, and the Echo Show 5 guide now describes the fix.

### Changed
- **The Kiosk Satellite boot animation and a plain wallpaper.** The Kiosk Satellite mark is the boot animation instead of LineageOS's. Its four bars bounce while Android boots, then settle and the house fades in around them. `scripts/make-bootanimation.py` makes it from the mark for each Show's screen. A fresh install gets a plain #444444 wallpaper. A Show still on the default wallpaper gets it with the update.
- **`echo_service button press`** sets the Echo Show 8's button layout: a short press turns the screen on and off and Android does nothing on a hold.
- **`echo_service status` reads the CPU's temperature sensor.** It read the first thermal zone, which is a virtual one that reads below zero on the Echo Show 8.

## 2026.10.1 - 2026-10-26

### Added
- **Echo Show 5 (2nd gen) on LineageOS 18.1.** The repository builds R0rt1z2's amazon-oss `cronos` tree with the Kiosk Satellite Edition layer on top. The screen, camera and Bluetooth work as they do in amazon-oss. The model reads Echo Show 5 2nd Gen (KS), and the Show names itself `echo-show-5-ks` and the end of its serial on the network.
- **Shared storage for Kiosk Satellite.** The Shows keep shared storage on sdcardfs instead of FUSE to save memory. Android 11 only lets an app into shared storage there with the legacy storage permission, which apps that target Android 11 or later never get. An app with all files access, as ks-install gives Kiosk Satellite, now sees all of shared storage, so its File Manager works (`patches/common/frameworks/base`).
- **EchoService on the Echo Shows.** `echo_service` sets a Show up from adb: Wi-Fi, Bluetooth, the time and time zone from the computer it runs on, adb over Wi-Fi, adb root, the lock screen, the language, the screen, the volumes, the network name, Kiosk Satellite, system updates and a log bundle to attach to an issue. It takes the place of BiscuitService, which stays on the Echo Dot. Kiosk Satellite reaches its system updates through the same calls.
- **Nothing to tap through on a fresh Show.** There is no setup wizard and no lock screen. adb works over USB from the first boot, so a computer only has to be allowed on the screen once. Allowed computers do not expire. Android's full screen tip is marked as seen. Once the Show is online, ks-install installs Kiosk Satellite as on the Dot and gives it device owner and every permission it needs before anything starts it. Kiosk Satellite 2026.10.41 and later then make themselves the home screen on its first run, so the kiosk is what comes back when anything else takes the screen. Android 11 takes the microphone from an app that is not in front, so Voice Satellite needs this. The launcher stays as Kiosk Satellite's fallback.
- **The real Wi-Fi MAC address in Home Assistant.** The image keeps per-network MAC randomization off, so the Echo Shows join every network with their factory address. Kiosk Satellite 2026.10.41 and later turn on Use real Wi-Fi MAC address on a fresh install, so its ESPHome device links with the one Home Assistant's network integrations already track.
- **System updates on the Echo Shows.** EchoService installs a release through TWRP as BiscuitService does on the Dot, in the Show's one slot. A Show's zip is larger than its cache partition, so it downloads to `/data`. If an install fails while it writes system, the Show stays in TWRP instead of starting a system that may not boot.
- **Leaner Echo Shows.** The image leaves out what a kiosk never uses: telephony, LineageOS's updater, AudioFX, print, backup, the secure element, the wallet and the apps for calendar, contacts, the clock, music, the gallery, the calculator, the browser, the camera and the recorder. SystemUI, WebView, Settings, the keyboard, the launcher and the file picker stay. The kernel's emergency reserve is 8 MB instead of 16 MB, which leaves a 1 GB Show about 30 MB more available. As on the Echo Dot, Android keeps one idle app in memory instead of up to 32, shared storage runs on sdcardfs instead of FUSE, Java heaps keep less free space and the metrics, incident, storage statistics and credential services, the notification assistant, autofill, backup and system tracing are left out.
- **The button keeps the screen and privacy apart.** The Echo Shows' power button is also their privacy button: the privacy chip turns privacy on and off on any press shorter than about 3 seconds, whatever Android does, so turning the screen off or on with it also turned privacy on or off. Now a short press only does privacy and holding the button for 3 seconds turns the screen on and off, as on Fire OS. `echo_service button menu` brings back Android's short press and power menu, and `echo_service privacy` says whether privacy is on.
- **Bluetooth both ways.** `echo_service bt pair` lets phones play to a Show as a Bluetooth speaker. `echo_service bt connect [name]` plays the Show's audio through Bluetooth headphones or a speaker instead. Android 11 runs one A2DP role at a time, so EchoService switches between them as BiscuitService does on the Echo Dot and keeps the last one across reboots. Kiosk Satellite's Bluetooth proxy keeps scanning in both.
- **Settings opens a paired phone's details.** A phone that asked for phone book or message access made Settings crash on its Bluetooth details, since the Shows leave those profiles out, so it could not be forgotten either. Settings now skips the profiles the image does not have (`patches/common/packages/apps/Settings`).
- **No Bluetooth error at boot.** The Shows leave out the contacts and telephony providers, which Bluetooth's phone book profile needed, so Bluetooth crashed at every boot and Android said it stopped responding. The image now turns off the Bluetooth profiles a kiosk has nothing for: phone book and message access, file transfer, tethering and acting as a keyboard. Audio both ways, AVRCP, the Bluetooth proxy's GATT and Bluetooth keyboards and remotes stay.
- **No Trust notifications.** LineageOS's Trust posted "Discover Trust" at every boot until someone opened its screen. Dismissing it did not count. After that it warned that SELinux is not enforcing and that the build is signed with public keys, which is true of every Echo image. A fresh Show now starts with Trust's introduction seen and its warnings off, from defaults the image sets in LineageOS's settings provider (`patches/common/lineage-sdk`). EchoService does the same on a Show set up before. Settings > Trust turns the warnings back on.
- **No clock on a sleeping screen.** LineageOS's ambient display showed a clock while the screen was off. A sleeping Show's screen now stays dark. `echo_service screen ambient on` brings the clock back.
- **The wake word over music on the Echo Show 5.** The microphones' FPGA also sends a copy of the speaker signal, which nothing used. The audio HAL now cleans the microphone with it before Android gets it: Speex's linear echo canceller below 1 kHz, and above it the Echo Dot's speaker removal across the two microphones, which also takes out the speaker's distortion a linear canceller cannot model, followed by 20 dB of gain. Amazon's own front end, which normalized the voice for Amazon's wake word engine and fought this canceller, is passed through. With music at 55%, vsWakeWord heard the wake word 10 times out of 10, against 3 with the stock audio path, and 9 times out of 10 at 75%. A fresh Show starts at 70% media volume (10 of 15), with Kiosk Satellite's media player and assistant volumes at their default 100. The canceller started from the one written for the Echo Show 8 in lineageos-echo-show and now reads the Echo Show 5's four channel stream too.
- **Amazon's wake words on the Echo Shows.** The image includes Amazon's wake word engine with the same models for Alexa, Echo, Computer, Amazon and Ziggy as the Echo Dot image. `biscuit-pryond` and the files from the Echo Dot's Fire OS 6.5.7.4 and DAVS now go to every Echo, since they all share the MT8163's 32-bit userspace. The Echo Shows set `ro.echo.pryon`. Kiosk Satellite 2026.10.41 and later offer it on a Show. `make check` fails an image without the engine.
- **`echo_mic_test`** prints the level of each channel of the microphone stream and can save it, to find a weak microphone.
- **The screen stays on.** The screen timeout defaults to never, so only Kiosk Satellite decides when the screen dims or sleeps. `echo_service screen timeout` changes it.

### Changed
- **Clean release builds.** `CLEAN=1 make <device>` empties the device's output folder before the build, since the build never deletes what an image stopped installing and the zip packs the whole folder. Release builds use it.
- **One layer for every Echo and one for the Echo Shows.** `common/config/common.mk` holds what every Echo gets and `common/config/show.mk` what only the Echo Shows get.
- **An Unreleased heading for one device.** A `## <device> Unreleased` heading marks only that device's builds as `-dev`, so work on one Echo no longer changes another Echo's release version.
