# Echo Show 8 (1st gen) changelog

All notable changes to the Echo Show 8 (1st gen) (`crown`) image are documented here. The [Echo Dot (2nd gen)](CHANGELOG-biscuit.md) and [Echo Show 5 (2nd gen)](CHANGELOG-cronos.md) have their own.

## Unreleased

### Added
- **Privacy timeout** ([#30](https://github.com/jxlarrea/lineageos-echo-kiosk-satellite/issues/30)). `echo_service privacy on` turns privacy on from adb. `echo_service privacy timeout <seconds>` has EchoService turn privacy back on once the microphones have been on that long, so the microphones stay off unless someone just held the button. The privacy chip's driver only lets software turn privacy on, so only the button turns the microphones back on.

### Changed
- **Updating from amonet 1 installs the amonet package from TWRP** ([#29](https://github.com/jxlarrea/lineageos-echo-kiosk-satellite/issues/29)). Unlocking said to run `fastbrick` again on a Show unlocked with amonet 1, but `fastbrick` does not run on a Show that is already unlocked. It now says to install R0rt1z2's amonet package from TWRP, as the XDA thread does. When `fastbrick` says the bootloader is already unlocked, Unlocking now says to check the TWRP version instead of taking the Show as on amonet 2.
- **Unlocking shows each device in its own collapsible section.** Each section opens from the device's name, so the page shows only the steps for your device.
- **Updates from your own server** ([kiosk-satellite#1229](https://github.com/jxlarrea/kiosk-satellite/discussions/1229)). A new guide covers updating an Echo on a network without Internet access from a folder on your own web server, such as a NAS. It has a script that mirrors the newest releases and the adb command that points the Echo at the folder.
- **The kernel version names the release.** It said `4.9.337-g3e46726afcbe-dirty`, with a build number that counted every kernel build on the build machine. It now says `4.9.337-kiosksatellite-crown-<release>`, such as `4.9.337-kiosksatellite-crown-2026.10.6`, with build `#1`.
- **Android's build string names the release.** Its build number was `eng.<user>.<date>`, as in `lineage_crown-userdebug 11 RQ3A.211001.001 eng.builde.20261030.161037 test-keys`. It is now the release, as in `lineage_crown-userdebug 11 RQ3A.211001.001 2026.10.6 test-keys`. The build fingerprint has the release too.
- **Joining a Wi-Fi network with a `!` in its name or password.** The guide's `wifi connect` command failed with `event not found` for a name like `FRITZ!Box 7590`, since bash and zsh read a `!` inside double quotes as a history command before the command reaches the Show. The guide now names `!` and `$` among the characters to type in a shell on the Show instead.

## 2026.10.5 - 2026-10-30

### Fixed
- **The Echo stopped rejoining a Wi-Fi network without Internet access** ([kiosk-satellite#1009](https://github.com/jxlarrea/kiosk-satellite/discussions/1009)). When a network the Echo was connected to by hand failed Android's Internet check, Android turned auto-join off for that network for good, while the Echo stayed connected. After the next restart or Wi-Fi drop the Echo never rejoined, which hit Echos on a VLAN that only reaches Home Assistant. Android now keeps auto-join on for such a network. A network a previous release disabled this way is enabled again when the update starts. This fix applies to every Echo.

### Changed
- **The Echo Show 8 guides cover macOS and a failed Kiosk Satellite download** ([#28](https://github.com/jxlarrea/lineageos-echo-kiosk-satellite/issues/28)). Unlocking says R0rt1z2's package does not run on macOS as shipped and links a workaround on the XDA thread, says to keep the Show off Wi-Fi until it is unlocked and names Fire OS 6.5.7.4 as known to work. The Echo Show 8 guide says what to do when the first-boot download of Kiosk Satellite fails.

## 2026.10.4 - 2026-10-30

### Added
- **Double tap to wake** ([#25](https://github.com/jxlarrea/lineageos-echo-kiosk-satellite/issues/25)). Android offered a Double tap to wake setting, but it did nothing. When the screen turned off, the touch driver put the touch chip to sleep and cut its power, so no tap could reach Android. The chip now keeps scanning while the screen is off. The driver now turns the screen on when two touches start within 400 ms of each other. No other touch reaches Android while the screen is off. Android's Double tap to wake setting turns it on and off. It is on by default.

### Fixed
- **GApps and Magisk survived an install of this image** ([#27](https://github.com/jxlarrea/lineageos-echo-kiosk-satellite/issues/27)). LineageOS runs its backup tool in every zip it builds for testing, which the Echo images are. It saves what `/system/addon.d` lists before the zip writes the system partition and puts it back after. Moving from another image with GApps or Magisk, such as R0rt1z2's, kept them, even with the data wiped. An account GApps added could then keep Kiosk Satellite from becoming the device owner. EchoService only takes an update from the device owner. The zip no longer runs the backup tool, so an install writes exactly this image. `make check` fails a zip that runs it. This fix applies to every Echo. The Echo Show 8 guide says what carries over from R0rt1z2's image and how to check that Kiosk Satellite is the device owner when an update does nothing.
- **Apps crashed when a filled-in text field became visible** ([#24](https://github.com/jxlarrea/lineageos-echo-kiosk-satellite/issues/24)). The image leaves out Android's autofill service to save memory, but Android's autofill code still called it when a text field that already had text and no focus came into view. The app crashed with a NullPointerException, for example YouTube Morphe on saving its settings to a file. Android now skips autofill when the service is not there. This fix applies to every Echo.
- **The device in a release zip's `release.prop`.** It read `ro.product.device=None` on every Echo Show release. Android 11 keeps `ro.product.device` out of the system `build.prop`, which the release step read it from. It now reads `ro.product.system.device`. Nothing used the line, since EchoService checks the device in the zip's metadata, so updates were never affected. `make check` now fails a release zip that names another device.

### Changed
- **One changelog for each device.** `CHANGELOG.md` is now `CHANGELOG-biscuit.md`, `CHANGELOG-cronos.md` and `CHANGELOG-crown.md`, with release headings such as `## 2026.10.15 - 2026-10-29`. A build takes its release from its own device's changelog, so an Unreleased section for one Echo never touches another's builds.
- **Setting the time server.** The Echo Show 8 guide has a new Time section. It covers using your own NTP server instead of `time.android.com` and changing the time zone later with `echo_service time zone`. Android 11 ignores an NTP server the router hands out over DHCP ([#25](https://github.com/jxlarrea/lineageos-echo-kiosk-satellite/issues/25)).
- **Builds leave the rest of the host usable.** A build used to take every CPU and stall the whole host until it finished. The build container now gets half the CPUs at the lowest priority and half the memory without swap, with one job for every 5 GB. metalava, which takes several GB a run, runs at most two at a time with 20 GB. `BUILD_CPUS`, `BUILD_MEMORY`, `BUILD_JOBS` and `BUILD_HIGHMEM_JOBS` change the limits. [Building](docs/building.md) covers them.

## 2026.10.3 - 2026-10-29

### Fixed
- **The camera HAL ran the Show 8 out of memory when the camera stayed open** ([kiosk-satellite#1209](https://github.com/jxlarrea/kiosk-satellite/issues/1209)). MediaTek's camera HAL was built for Android 9. For every frame it creates two objects that Android 11 no longer frees completely, so `camerahalserver` grew by about 35 bytes a frame and logged six lines a frame while the camera was open. With Kiosk Satellite's motion detection on, that came to up to 3 MB an hour. After about 10 days the swap filled and the low memory killer started closing apps, Kiosk Satellite included. The shim the camera HAL loads now frees those objects as Android 9 did, and its memory stays flat.
- **Music sounded tinny and warbled while Kiosk Satellite listened** ([#20](https://github.com/jxlarrea/lineageos-echo-kiosk-satellite/issues/20)). Amazon's audio driver moves playback onto its call path whenever a microphone capture starts. That path is made for calls: it filters out the bass and turns playback down while it hears the microphones. The audio HAL only took playback back off it for the captures it sends through Amazon's ASR pipeline itself. With Capture mode set to Voice communication in Kiosk Satellite, or after Kiosk Satellite fell back to that source by itself, music stayed tinny and warbling for as long as the microphones were open. Playback now leaves the call path at the start of every capture unless Android is in a call.

## 2026.10.2 - 2026-10-27

### Fixed
- **A system update from TWRP 3.2.3 could leave the Show in a boot loop** ([#13](https://github.com/jxlarrea/lineageos-echo-kiosk-satellite/issues/13)). The image needs amonet 2 and its TWRP 3.7.0_9-0, but an update runs in whatever TWRP the Show has. On a Show still on amonet 1 and its TWRP 3.2.3, the update left the system half written. The update step in TWRP now checks the TWRP version first. With anything other than 3.7.0_9-0 it writes nothing and starts Android again, and EchoService reports why in Home Assistant and Kiosk Satellite. This applies to updates from this release on.
- **Camera streams and videos in High profile H.264 fell back to software decoding** ([#15](https://github.com/jxlarrea/lineageos-echo-kiosk-satellite/issues/15)). MediaTek's hardware decoder told Android it handles High profile only at its lowest level, although it decodes High up to level 4.1 at 1080p at about 150 frames a second. Its size limit also read as at most 1088 pixels high, which ruled out portrait video. Kiosk Satellite's WebView and players such as ExoPlayer then used Android's software decoder, which is about four times slower on the Show and stalled camera streams. Android now lists High profile up to the same level as Main for this decoder and accepts portrait video up to 1080x1920, so these streams play on the hardware decoder.

## 2026.10.1 - 2026-10-27

### Added
- **Echo Show 8 (1st gen) on LineageOS 18.1.** The repository builds R0rt1z2's amazon-oss `crown` tree with the Kiosk Satellite Edition layer the Echo Show 5 has: EchoService, Kiosk Satellite on first boot, Amazon's wake words, the echo canceller, Bluetooth both ways, system updates and the same debloat. The model reads Echo Show 8 1st Gen (KS). EchoService names the Show `echo-show-8-ks` and the end of its serial on the network.
- **Privacy and the screen on separate presses.** The Show 8's privacy chip turns privacy on and off at the release of a hold of about a second and a half. Any press turns it off. A short press now turns the screen on and off. Android does nothing on a hold, so a privacy hold no longer turns the screen off as well. While privacy is on, Android leaves the press to the chip.
- **Amazon's far-field front end for Kiosk Satellite.** The audio HAL now sends Kiosk Satellite's microphone capture through Amazon's ASR pipeline, the one Amazon's own wake word listens to, with its echo canceller and beamformer over all four microphones and the FPGA's copy of the speaker signal. Its output comes out about 25 dB quieter than a plain capture, so the HAL raises it by 24 dB with a soft limit. With 40 test voices played from 2.5 m at 50% volume, Kiosk Satellite's wake word engine caught 14 over music instead of 5 with the image's own echo canceller. Over the assistant's voice it caught 17 instead of 11, as many as in a quiet room. The image's echo canceller stays loaded and passes the microphones through.
- **The Kiosk Satellite boot animation and a plain wallpaper.** The Kiosk Satellite mark is the boot animation instead of LineageOS's. Its four bars bounce while Android boots, then settle and the house fades in around them. `scripts/make-bootanimation.py` makes it from the mark for each Show's screen. A fresh install gets a plain #444444 wallpaper.
- **The Echo Show 8 guide.** [docs/echo-show-8.md](docs/echo-show-8.md) covers installing, setting up and updating the Show, its button, volume, Bluetooth and device commands. Unlocking and Getting into TWRP have sections for the Show 8, and the Echo Shows' amonet 1 sections are now called Updating from amonet 1.

### Fixed
- **The microphones read zeros after privacy ended with a short press.** The Show 8's privacy circuit lets the microphones back on at any press of the button, but its kernel driver only reported presses of half a second or more. After a short press the sound driver kept the microphones off and their FPGA lost its firmware, so every recording read zeros until a reboot. The driver now reports the microphones back as a long press does.
- **The microphone level dropped by up to 25 dB after a loud sound.** EchoParts' noise suppression, on by default, sends every plain microphone capture through Amazon's VoIP pipeline. Its AGC turned the level down after a shout or the start of music and kept it there until the stream closed, so Kiosk Satellite heard a quiet room at -75 dBFS instead of -48 dBFS. EchoParts' noise suppression is now off on a fresh install. Amazon's VoIP pipeline also stays in passthrough.
- **Streaming stalled on Wi-Fi networks with several access points.** Android 11 looks for a better access point after every scan while a connection carries little traffic. The Echos' Wi-Fi drivers report no traffic at all. On a mesh network Android moved an Echo Show 8 between access points every 20 seconds, even in the middle of a voice conversation. Each move stalled audio and dropped Home Assistant. Android also ranked access points by a throughput estimate that these drivers get wrong, so it picked a weak mesh node over the router next to it. Android now keeps the access point it connected to and picks one by signal strength, preferring a 5 GHz network down to -50 dBm. This applies to every Echo.

### Changed
- **Release images are checked against the other Echo Show.** `make check` now also fails an Echo Show 8 or Echo Show 5 image that carries the other Show's settings, audio pipeline, boot animation or hostname, and fails an Echo Dot image with the Shows' boot animation or wallpaper. `make test` fails if either Show inherits the other's device layer or a shared layer sets what each device sets.
- **50% master volume on a fresh Show 8.** A fresh install starts at master volume 8 of 15, which Kiosk Satellite shows as 50%. The Show 8's speakers are much louder than the Echo Show 5's. At 70% a voice across the room ends up about 18 dB under music, where no setting caught more than 6 of 10 wake words.
